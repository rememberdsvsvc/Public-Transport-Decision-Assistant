# 原型范围声明

## 必须真实可用

| 能力 | 所服务的问题 |
|---|---|
| 选择出发地、目的地、时间和计划行程。 | 1.1、1.2 |
| 将所选行程传递到中断信息页面。 | 1.1、1.2 |
| 显示模拟的受影响路段、状态和到达影响。 | 1.2、2.1 |
| 比较并选择可用的行程方案。 | 1.1、2.1、2.2 |

## 可以模拟

- 本地 SQLite 行程和中断数据。
- 固定行程情境和硬编码的中断状态。
- 本地提交的评价及人工记录的评分。

## A2 不构建

- 实时网络数据、实时警报、账户、认证、支付或票务。
- 运营方流程、调度工具、乘客支持和服务恢复。
- 关于长期行为、公平性、治理或环境结果的结论。

## 构建顺序

确认四条必须真实可用的流程，执行固定情境技术核查，准备测试工具，进行试点并修订，之后在第 7 周前冻结评估版本。为每项依赖分配负责人和第 6 周结束前的完成日期。
