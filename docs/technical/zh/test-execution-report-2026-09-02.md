# 测试执行报告 - 2026-09-02

## 1. 测试目的

验证当前 iOS 原型是否能够构建、安装、启动，并确认核心业务流程的状态传递是否已在源码中实现。此报告属于 DECO6500 的 1.2“原型与技术”证据，不代替参与者可用性测试。

## 2. 测试范围

本轮测试覆盖以下流程：

1. 编译并生成 iOS 模拟器应用。
2. 安装、启动并检查首页渲染。
3. 检查“选择行程 -> 中断信息页”的状态传递。
4. 检查“中断信息页 -> 决策支持页”的状态传递。
5. 检查“选择方案 -> 评价页”的状态传递。
6. 检查“提交评价 -> 确认状态”的逻辑。

未覆盖真实交通数据、外部提交、实时提醒、真机兼容性，以及参与者的理解和决策行为。

## 4. 测试流程

1. 使用 `xcodebuild` 编译项目，并将构建产物写入临时目录。
2. 启动 iPhone 17 Pro 模拟器。
3. 安装应用并通过 Bundle ID 启动。
4. 截取首页，确认界面是否渲染。
5. 阅读核心 View、Journey 状态模型和数据库服务，核对每个页面之间的状态传递与导航条件。
6. 记录通过、失败、仅源码验证和需人工复测的结果。

## 6. 已发现问题与优化建议

| 优先级 | 问题或风险 | 影响 | 建议 |
|---|---|---|---|
| 中 | `InformationCard.swift` 被加入 Xcode 的 Copy Bundle Resources。 | 当前不阻断构建，但属于错误的资源配置，持续产生警告。 | 在 Xcode 的 Target -> Build Phases -> Copy Bundle Resources 中移除该 Swift 文件。 |
| 中 | 第一次启动时出现短暂白屏。 | 可能影响测试参与者对系统稳定性的第一印象。 | 在重置模拟器和真机上复测；记录首次界面出现前的时间。若可重复，再检查主线程上的初始化工作。 |
| 高 | T-03 至 T-06 尚未完成真实点击式端到端验证。 | 源码存在导航逻辑，不代表运行时一定能完成每一步。 | 使用[技术核查模板](technical-verification-template.md)在模拟器上手动完成四个情境，并保存去标识化截图/观察。 |

## 7. 结论与下一步

本轮证明原型可以构建，且首页能够在模拟器中启动。核心页面之间的状态和导航逻辑在源码中存在，但后续页面尚未完成真实触摸操作验证，因此不能宣称完整端到端流程已经通过。

下一步由开发同学执行 T-03 至 T-06 的人工运行时核查，修复或确认构建警告，并在参与者测试前完成一次试点。参与者的可用性、理解、情境使用和决策信心应按照[可用性测试计划](../../testing/interview/zh/usability-test-plan.md)另行收集。
